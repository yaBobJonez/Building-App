# АСУ будівництва (MVP)

Робота у репозиторії має відбуватися за **Git Flow**.
Для цього є такі види гілок:

- `main` → стабільний код, готовий до використання; суди напряму не комітимо
- `develop` → (дефолтна) гілка для інтеграції функціоналу, тут формується наступна версія
- `feature/*` → створюємо окремі гілки для кожної із своїх фіч
- `bugfix/*` → окремі фікси для main, якщо будуть
- `release/*` → будемо відокремлювати із main, коли MVP готовий

Щоб розпочати роботу, клонуйте репозиторій і зайдіть до нього:

```bash
git clone https://github.com/yaBobJonez/Building-App.git
cd Building-App
```

Ніколи напряму не пушимо до main чи develop, щоб уникати конфліктів! Вся робота ведеться в окремих гілках-фічах. Також не забуваємо стягувати зміни з develop перед початком роботи.

## Працюємо над своїм функціоналом

Щоб розпочати роботу над новою фічею (частиною реалізації) — перейдіть на develop, стягніть собі зміни, якщо якісь були, створіть нову гілку для фічі (наприклад, feature/dashboard-ui):

```bash
git checkout develop
git pull origin develop
git checkout -b feature/НАЗВА-ФІЧІ-ТУТ
```

Коли ви думаєте, що реалізували достатню частину роботу — додайте зміни в індекс і створіть коміт (бажано ділити логічні частини реалізації на кілька комітів):

```bash
git add .
git commit -m "Опис що ви зробили у цьому коміті"
```

Якщо робота над фічею завершена (або просто хочете, щоб зміни вже були доступні всім) — пуште на репозиторій:

```bash
git push -u origin feature/НАЗВА-ФІЧІ-ТУТ
```

Після цього відкрийте на GitHub новий пул-реквест (PR) із (compare) вашої гілки feature/* до (base) develop. Якщо реквест прийнятий та зміни обʼєднані в develop, гілку загалом можна видаляти (або залишити на ваш розсуд).

## Оновлюємо фічі змінами з develop

Якщо виникне ситуація, що ваша гілка фічі відстала від develop, а ви ще не робили пул-реквест (наприклад, за паралельної роботи), рекомендую перейти в develop, стягнути зміни з репозиторію, повернутися на свою гілку фічі і спробувати обʼєднати зміни.

```bash
git checkout develop
git pull origin develop

git checkout feature/НАЗВА-ФІЧІ-ТУТ
git merge develop
```

## Базові корисні речі

- Переглянути список наявних гілок: `git branch -a`
- Статус поточної гілки (де ви і що змінено): `git status`
- Перейти на іншу гілку: `git checkout НАЗВА-ГІЛКИ`
